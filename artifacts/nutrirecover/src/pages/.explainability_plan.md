# Explainability Improvement Plan

## Current State Analysis

### What already exists:
1. **`deficiency-prediction-engine.ts`** — Has lab/symptom contribution scores, confidence %, reasons per nutrient, priority levels
2. **`recovery-engine.ts`** — Has `computeNutrientPriorities()` with lab reasons, symptom reasons, diet/BMI reasons. Has `generatePlanExplanation()` with categorized reasons
3. **`food-recommendation-engine.ts`** — Has `selectionReason` with % DV details, `priorityScore`
4. **`meal-plan-generator.ts`** — Has `nutrientProgress` per meal, but no meal assignment reasoning
5. **`suggestion-engine.ts`** — Has `reason` (simple string) and `expectedImprovement`, but no confidence/lab/symptom breakdown
6. **`Dashboard.tsx`** — Shows `activeNutrients` (priority+score), `insights` array

### What's missing:
1. **Suggestion engine** doesn't include confidence %, lab contribution details, symptom contribution details
2. **Food recommendation engine** doesn't surface confidence/contribution data to UI
3. **Meal plan generator** doesn't explain *why* a food was assigned to a specific meal
4. **Suggestions page** shows only reason + additions, no depth
5. **Dashboard** shows deficiency count but no per-deficiency explanation cards

## Changes Required

### Backend

#### 1. `suggestion-engine.ts` — Add explainability fields to suggestions
- Add `confidence: number` (from deficiency prediction)
- Add `labContributions: { nutrient: string; value: number; contribution: number; explanation: string }[]`
- Add `symptomContributions: { symptom: string; contribution: number; explanation: string }[]`
- Update reason to include why the specific gap exists with plain language
- The route `dashboard.ts` already fetches dashboard; the suggestions route is separate

#### 2. `food-recommendation-engine.ts` — Add contribution context to recommendations
- Add confidence field since it comes from deficiency prediction
- Add detailed contributions for lab and symptom

#### 3. `meal-plan-generator.ts` — Add meal assignment reasoning per meal slot
- Add `mealReason: string` explaining why foods were chosen for each meal

#### 4. `recovery-engine.ts` — Keep existing explanations, add confidence to priorities
- Already has reasons, just needs better surfacing

### Frontend

#### 5. `Dashboard.tsx` — Add deficiency explanation cards
- Replace simple deficiency count with cards showing per-nutrient: priority, score/confidence, lab contributions, symptom contributions, food sources
- Add explanation sections using existing data

#### 6. `Suggestions.tsx` — Add confidence, lab/symptom breakdown
- Show confidence badge per suggestion
- Show lab value contributions table
- Show symptom contributions table
- Keep existing design, add collapsible explanation sections

#### 7. No changes to api.schemas.ts (auto-generated) — Use extensible JSON responses

## Key Principle
- Every explanation must answer: "Why this deficiency? Why this food? Why this meal? Why this nutrient?"
- Use simple medical language (plain terms, no jargon)
- Show confidence as percentage
- Show lab values and symptoms that contributed
- Maintain existing UI design patterns
